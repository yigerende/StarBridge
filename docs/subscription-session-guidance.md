# 订阅 Session 失败提示

2026-11-20 用户授权修复、推送 GitHub 并更新正式环境。

订单列表、详情和两端办理总览显示 Session 失效或无法刷新、缺少 sessionToken/Cookie、办理账号不一致的具体提示。判断只使用已持久化的固定错误类别、当前付款后警告、付款提交/成功时间与账本；不读取异步诊断文件、不增加上游请求、不修改任何执行、重试、代理、钱包或凭据保存逻辑。

仅最终失败且没有付款提交/成功证据、费用为零或实际已释放冻结时，提示获取新的完整 Session 重新提交。已付款的后续异常保持成功/已结算，提示联系支持处理原单、不要再次下单或付款。付款已提交或费用状态不确定不引导重下。已恢复的成功单不展示历史异常；前一轮的具体错误不能覆盖本轮最终原因。网络故障不归入 Session 失效。

原用户 API 请求、响应字段、状态、鉴权和幂等均保持，只优化 payment.message 与最后对应 events[].message。HTTP 查询成功仍为200；上游401不变成星桥API401。网页办理总览增加 message 展示字段，/api/v1/activity 保持原字段。历史记录通过只读投影显示提示，不回写订单或事件。提示文字面向用户阅读，文档明确状态字段用途与付款边界。OpenAPI 2.9.1，操作数仍30。

正常/进行中订单不增加原因查询；异常记录以当前页ID一次批量查询，账本按当前订单集合聚合，不逐行请求。500笔独立失败订单验证单次查询。
