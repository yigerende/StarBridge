# 代退可选邮箱接码地址

2026-11-20 用户要求完成开发、推送 GitHub 并更新星桥正式环境。

## 行为

- 单个办理增加选填的邮箱接码地址；批量继续支持三列，第四列可填地址。
- 网页与用户 API 的 accounts[] 增加可选字符串 email_code_url；省略或空串等同旧请求。required、响应、路由、旧请求序列化和幂等摘要均保持，旧客户端不需修改。
- 先按原规则尝试密码和上游要求的 2FA，验证后仍要求邮箱码才读取本单链接。正常登录、密码错误、未填写链接时不会访问邮箱站；没有链接保持原来的额外验证处理。若上游先要求邮箱码才提供 2FA，则取码后继续原 2FA，不能越过上游步骤。
- 主办理、核实重登、个人套餐兜底共用接入；重试从订单加密凭据读取地址。同一登录继续原 Cookie 和子号代理会话。
- 读取 Space 已有文本/HTML/JSON/Base64 邮件解析及可通过完整链接访问的专用适配。必须额外提供查询密码的邮件站不在本次仅链接字段的范围内，不使用账号登录密码代替邮箱查询码。
- 默认取码等待最多120秒、每5秒查询、最多30次读取、单次15秒与2 MiB响应限制；仅需要邮箱码的订单承担等待。旧时间戳及本次已提交码过滤，无时间戳链接由上游校验验证码，无法保证链接返回的一定是最新邮件。
- 邮箱码提交仍用原协议，提交后若再次要求邮箱码或密码则停止，避免无限循环。没有自动重发邮件或改密码。

## 隔离与保密

地址随原账号凭据加密保存，不进入普通订单详情、列表或管理员已有密码/2FA白名单。读取仅允许公网HTTP(S)，逐连接和重定向校验并固定公网IP，拒绝内网/回环/云元数据及嵌入用户名密码。邮箱请求不带OpenAI Cookie、Authorization或业务代理。独立邮件站Cookie仅用于本站适配。失败只显示固定原因，邮件站网络故障不触发子号代理冷却。

原 upstream.py、merge_v2.py、refundworker 和注册核心未改；原调度、业务重试、未知提交防重、扣费/释放不变，不重放历史订单。
