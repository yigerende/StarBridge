# 停用账号再次提交限制

2026-11-12，用户明确授权完成配置、两端受理拦截、运营解除后推送 GitHub 并更新正式。

## 使用

运营端「代退资源与调度 → 调度与恢复 → 账号停用后的再次提交」设置允许次数，范围 0～10，默认 0。首次上游明确账号停用不计作再次提交；设为 2 时再允许创建两笔订单，第 3 笔返回 409。原订单内登录、恢复、清理、代理切换与扣费规则不变。

网页与 API 通过同一个受理事务检查，以目标邮箱规范化后全站统计。新受理订单才计数；同一幂等请求重发、被拒绝的请求、原单重试不计数。已受理后取消仍计一次。批量中任一账号超限整批回滚，不创建部分订单、不冻结积分、不消耗次数。

调度页下方显示停用账号邮箱、原因、首次发现/最近确认时间、再次提交/允许次数与限制状态，支持搜索、状态筛选、10/50/100/500 分页及排序记忆。保存次数后列表同步刷新。运营管理员可确认解除并清零次数，操作写入审计；已受理订单继续收尾。旧订单的迟到诊断不会重新锁住已解除账号；解除后新订单再次确认停用则开始新的限制周期。

## 证据边界

只接受子号 account_unavailable 且明确 account_deactivated/account_deleted/account_banned/account_disabled/account_suspended 的上游错误。一般 403、网络错误、密码错误、邮箱验证、个人空间停用观察与母号错误不触发。调用层不改原执行协议及原 worker。

新增 deactivated_resubmit_limit 字段与 refund_account_restrictions 表。首次初始化从正式自身已保存的明确诊断建立限制，统计首次发现之后的新订单，含本次排查账号；不重跑、不修改历史订单、钱包或资源配置。该初始化仅执行一次，之后重启不重复扫描历史，也不覆盖已解除的记录。
