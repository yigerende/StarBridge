# 代退登录 403 的代理会话恢复

2026-11-25 用户确认代理出口故障，要求仅在子号登录返回 403 后的重试重新生成当前代理会话。新会话必须保存到原订单，后续步骤及恢复使用最新会话；完成测试后推送 GitHub、更新正式，切换前检查在途。

2026-11-26 用户进一步明确：登录403只要按原规则进行重试，就必须更新代理会话，不能因响应里的页面标记跳过。适配层及存储层均取消这类排除条件；标记只作为诊断信息保留，不决定是否换会话。

## 行为

- 仅主办理子号 `login()` 内可重试的 403／代理 CONNECT 403 使用此恢复，包括响应带页面标记或 `cf-mitigated: challenge` 的情况。响应类型与原因字段不再阻止更新代理会话。原本不允许重试的明确账号停用、密码错误等仍按原规则结束；提交代退、个人套餐查询、结果核实和母号请求不扩大为这条规则。
- 沿用当前代理配置的厂商、国家和会话时长，替换本笔订单的会话标识，不换供应商、不全局冷却。其他真实连接故障仍走已有主备、冷却流程。
- 原调度器先决定是否还有重试次数，并沿用原间隔。需要下一轮时，与调度状态在同一事务加密保存新代理会话；没有重试机会时不额外创建会话。
- 自动恢复关闭时，保留原进程内登录次数和等待。在下一次登录建立连接前，由私有 checkpoint 保存新会话，确认成功才使用；确认丢失则停止，不使用旧地址继续请求。
- 登录成功后的提交，以及普通重试、进程重启、结果核实和兜底登录都读取原订单最新保存的会话。母号代理保持原绑定；原单、冻结、结算及未知提交防重规则保持。
- 皇冠/IPRoyal、CLI、1024、711 使用已有厂商格式。“其他（原地址）”没有可替换会话参数，仍按原配置重试。不同会话标识不保证代理商一定分配不同 IP，不增加出口 IP 探测请求。

## 实现边界

仅 StarBridge 适配层和存储层变动。原 HUIXU runtime、refundworker、注册核心均未修改；不新增表或修改客户 API。正常成功路径不增加上游请求或数据库查询，只在失败重试时保存新绑定。原单最新绑定保存在 `refund_child_proxy_sessions`，历史绑定不删除。

## 验证

使用合成账号、模拟 HTTP 和独立临时 PostgreSQL；不调用真实账号、代理厂商或退款接口，不重放历史订单。

- Python：调度重试与进程内重试、连续失败次数/间隔、新会话成功后提交、ACK 丢失、不可重试密码/停用错误、带页面标记的403、非登录 403、代理 CONNECT 403；原网络主备回归。
- Go：四厂商会话格式、同代理更新、重复完成/并发完成/重复 checkpoint、失效租约、重启、配置修改后的订单绑定、重试耗尽、普通重试及兜底复用、冻结/结算及未知提交保护。
- 发布：GitHub 原目录拉取预构建，新镜像隔离验证，三业务空闲和备份后通过现有更新器切换，保留正式配置数据；结果以生产 runbook 为准。
