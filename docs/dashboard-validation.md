# 统一工作台与运营概览（2026-11-10）

本轮完成后仅推送 GitHub。正式环境由用户使用“更新 → 准备完成 → 立即重启”更新；本轮不连接正式 SSH、不调用正式更新器。

## 页面与数据口径

- 用户工作台：紧凑的账户、可用/冻结积分及会员信息，注册/订阅两个办理入口，当前待办，混合排序的最近 8 笔订单，公告与帮助。两个首页均不分业务 Tab。
- 运营概览：今天/近 7 天/近 30 天/自定义日期（最多 366 天），默认只统计客户业务，可包含管理员。新增订单包含订阅和注册；“新增中已完成”为期间新增订单的当前完成数，部分交付单独注明。已付但生效/续费尚待处理不显示完成。
- 净结算积分使用统一 ledger 的 charge/refund 实际金额；充值、兑换码、调账、冻结、伙伴奖励不计入。按北京时间划分日期，退款可以形成负值，趋势图在零线以下展示。
- 当前待办、队列、最近订单独立于历史日期筛选；全站待核查风险包含未登录访问，风险入口能查看全部时间的未核查记录。
- 订阅与注册队列分别展示排队/执行/待核实；受理开关和调度开关来自实际配置，不将开关或订单状态伪称为服务健康。
- 注册交付按账号数展示，和订单笔数分开。用户可领取数只包含交付后 72 小时内的记录；24 小时内到期提示跳转最早到期订单。平台没有“首次领取”标记，因此文案是“可领取”，不是“未领取”。
- 付款不明提示保留冻结并禁止重复付款；已付款后的生效/续费问题使用独立待办。待办链接携带业务、状态或订单号，打开订单详情或我的账号的对应订单。切换业务 Tab 清除前一业务的订单/状态筛选。

## 实现边界

Python 主后端各提供一个概览 API，同一数据库只读事务中汇总，无逐卡片上游请求。并发且相同账户/角色/筛选的请求合并为一次在途查询，完成后立即删除，不使用服务端结果 TTL 缓存。不同账户隔离。

两个首页独立加载，避免为了打开首页加载办理表单和整个运营模块。前端保留当前账户最近快照，返回页面立即显示并后台刷新；退出或会话失效清除快照。存在在途任务时每 10 秒刷新，页面隐藏或离开后停止；SSE 变更合并刷新，处理中收到的事件不会被丢弃。出错保留已有内容并提供重试。

没有数据库结构迁移，没有修改支付、冻结、扣费、退款、注册引擎或更新器执行逻辑。注册端改动仅限原平台报表的管理员范围筛选和门户详情深链；411 文件源清单核验通过，374 文件未改，37 项接入差异，原引擎保持不变。
