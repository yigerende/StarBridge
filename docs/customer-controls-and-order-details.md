## 功能边界

统一功能开关包含：工作台、注册办理、我的账号、订阅办理、结账链接、续费管理、代退办理、订单中心、资金中心、开发接入、伙伴计划、会员中心、接口文档、联系客服、个人设置。自定义菜单沿用逐条启用设置和服务端访问校验。

关闭功能同时影响菜单、页面渲染和对应用户接口。管理员进入用户端或使用用户 API 也遵循开关；`/api/admin/` 仍按管理员身份授权。原注册执行核心、已经受理的任务和会员计费权益不随菜单关闭而改变。

- `subscribe` 和 `links` 按创建订单的 `workflow` 独立判断，包含统一 API 和三个网页流程入口。关闭结账链接不会关闭订阅内的提链步骤。
- `renewal` 控制独立续费管理；订阅订单自身的付款后续费处理继续执行。
- `register` 控制注册报价、地区和下单；`accounts` 控制领取与导出；`orders` 控制三类订单查询。办理关闭后，只要订单中心仍开启，就可查询原单。
- 关闭父办理菜单但保留子功能时，保留可展开的父分组，办理链接不可点击。
- 关闭开发接入后，已有 API 密钥也无法调用用户开放 API。关闭个人设置不影响登录初始化和退出。
- 客户通知流与运营通知流分别为 `/api/order-updates`、`/api/admin/order-updates`。关闭订单中心终止客户流，但不注销有效会话；真实会话撤销才触发退出。管理员在客户流中也仅收到自己的订单事件。
- 资金流水保留账本和金额；订单中心关闭时，不投影三类订单详情链接。

## 用户 API 文档

统一文档为 2.4.0，共 32 个操作（主应用 23、注册 9），47 个导航锚点。新增可用功能与权限表、每个操作所需功能、订单 `workflow` 的独立权限和 HTTP 403 的处理说明。403 只表示该次请求被拒绝，不代表原订单失败或未扣款。

完整检查引用、操作标识、请求字段、响应示例及业务排序。文档仍只包含客户接入内容，不列运营或内部执行接口。348 个示例通过 JSON Schema 校验；其中请求里的银行卡号和 CVC 占位符仅在校验器中替换为合成测试值，文档仍提示用户自行填写授权资料。
