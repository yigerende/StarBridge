# 母号凭据编辑与连续失败保护

2026-11-14。用户授权修复、推送 GitHub 并更新正式；补充明确计数对象是提交代退的目标账号邮箱，绝不是星桥登录用户。

## 保存与回显

母号编辑原先把资源列表的统计、状态等只读字段一起提交给内部严格 JSON 接口，触发“请求参数格式不正确”；粘贴的 Session / AT 解析本身正常。表单现在按白名单提交可编辑字段，代理编辑同步处理。未更改的凭据提交空值，避免仅修改名称时重写运行凭据；已有运行/管理锁继续生效。

完整 Session 以独立 AAD 加密存储，仅管理员审计接口返回，响应禁止缓存；列表和用户接口不返回凭据。编辑时读取完整 Session，历史记录没有保存原 JSON 的则显示真实 AT。替换为纯 AT 或刷新 AT 时清除旧完整 Session，防止回填过期凭据。异步加载期间禁止保存和修改凭据，关闭/重开对话框时丢弃旧响应。

## 调度与恢复配置

所有配置仍在代退资源与调度 → 调度与恢复，沿用原设置表，不新增第二套配置。

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| 同母号团队会话失败次数 | 3 次 | 身份一致但未取得目标团队会话时，达到此次数或原登录重试耗尽后，先清理再按原换母号规则续办。0 关闭该保护。 |
| 母号自动停用的不同账号数 | 2 个 | 同一凭据/代理版本连续影响多个不同目标账号，自动将该母号 enabled 置为 false，并显示原因和时间。0 关闭自动停用。 |
| 代退账号连续失败订单数 | 4 笔 | 按目标邮箱全站统计最终 failed / banned 订单，原因不限。第 4 笔后拦截新的提交，返回409且不冻结资金；0 关闭拦截。 |

母号计数只接受母号侧故障或达到阈值的目标团队会话故障；子号密码错误、邮箱验证、子号代理/登录服务故障不作为母号失效证据。一次订单在同一母号版本只计一次，同一目标反复失败不冒充多个账号。成功进入目标团队、更新母号凭据/代理或人工重新启用后重新计数。自动检测不能擅自重新启用已停用母号。

换母号保留原单、价格和冻结，只在清理确认并完成延迟成员观察后重新分配；本单不再分配刚失败的母号版本。新母号重新计算登录重试预算，总换号次数仍受原配置限制。其他母号忙碌可继续等待，所有可尝试母号失效或换号次数耗尽则结束并按原规则释放；已提交、已受理或结果未知的订单不走该切换路径。

账号限制与星桥用户、API 密钥无关。原单内部重试和重复回报不累计，Idempotency-Key 重放仍返回原单；成功订单清零连续失败，未执行的撤回不计入失败。运营在同页的“代退账号提交限制”查看邮箱、原因、次数和时间并解除。原明确停用账号限制仍独立生效；同一张限制表保存原因及计数。混合批量受理事务保持原子性，任何账号被限制则整批不冻结。
