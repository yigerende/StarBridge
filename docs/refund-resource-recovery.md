# 代退母号检查与异常资源恢复

2026-11-12。用户授权与分页、称呼登录、母号管理、子号网络故障即时切换联合发布。正式数据、配置、历史订单和钱包保持；不补跑历史申请。

## 正常流程

选定母号后并行查询席位、完整成员和邀请，复用结果继续邀请。运营办理流程显示“检查母号”及实际耗时。母号所有查询、邀请、移出均使用该母号专属代理，不使用子号备用、不回落直连。

账号密码和 2FA 登录后默认查询并记录个人套餐，随后继续原空间选择流程。可关闭这一次观察；提交所需的核实基线、未知结果核实、移出后的套餐兜底不受此开关影响。正常成功不进入异常观察等待，不增加固定睡眠。

## 异常与兜底

- 母号无空位或目标团队选择 409：核查席位及残留，保护母号、管理员、本单子号、其他在途和管理操作中的账号；普通残留先写入持久清理责任，再移出并复查。
- 移出/撤销的 HTTP 200 不是完成依据。并行复查成员和邀请；未清理、超时及结果不明继续维护，不直接释放该资源给下一单。
- 邀请、登录异常结束后保留独立清理任务。后台检查迟到入组与残留邀请；发现残留后重新开始观察，连续两次干净检查且观察期结束才解除对应子号的跨母号限制。
- 允许确定是母号问题时换号，但已邀请的子号必须先完成清理和观察；未知提交不换号、不重复提交。
- 母号明确故障达到阈值进入冷却，满员未清理立即隔离。冷却不修改管理员启用开关；旧凭据的失败不能覆盖新配置。
- 多个不同子号在同一登录阶段遇到上游 500/429 等故障时触发登录保护，到期只放行一笔探测。死号、密码错误和邮箱验证不触发此共享保护，原有处理保持。母号清理不受登录保护影响。
- 子号明确网络故障由独立接入层先同步记录冷却和待切换标志，再结束当轮，后续按原恢复预算使用备用。母号故障不触发子号代理冷却。未知提交仅核实，不能借换代理重放。
- 费用释放与资源清理分开。订单结束仍保留维护责任；多次清理失败转低频检查并在运营页面展示。人工从上游移出后，下次检查可自动识别，无需伪造订单成功或重新扣费。

## 调度与恢复配置

| 配置 | 默认 | 范围 | 生效位置 |
| --- | --- | --- | --- |
| 查询并记录办理前个人套餐 | 开启 | 开/关 | 下次领取的执行配置 |
| 母号连续失败次数 | 3 | 1～10 | 母号明确故障统计 |
| 母号故障冷却 | 300 秒 | 30～3600 秒 | 母号故障后隔离 |
| 异常清理后观察 | 60 秒 | 30～1800 秒 | 异常结束或发现残留后 |
| 清理重试间隔 | 30 秒 | 5～300 秒 | 后台残留检查 |
| 转低频前失败次数 | 3 | 1～10 | 后台维护失败 |
| 低频重试间隔 | 300 秒 | 60～3600 秒，且不短于普通间隔 | 多次失败后的维护 |
| 登录保护不同账号数 | 3 | 2～20 | 同阶段上游登录故障 |
| 登录故障统计窗口 | 60 秒 | 10～600 秒 | 仅计窗口内不同账号 |
| 登录恢复探测间隔 | 30 秒 | 5～3600 秒 | 登录保护后单笔探测 |

上述配置只影响相应异常路径。已有子号主备冷却、母号换号预算、订单恢复与套餐兜底继续用原配置，不另建重复选项。固定保留租约、防重、身份保护、清理确认和至少两次干净复查等正确性要求。

“调度与恢复”同时展示故障母号和清理任务，支持搜索、10/50/100/500 分页、排序记忆与立即检查。立即检查只调整下次检查时间，不修改订单、费用或资源启用状态；全部接口后端管理员鉴权。

## 修改位置

- `runtime/resource_guard.py`、`refund_runner.py`：前置母号检查、目标团队 409、移出后并行复查、观察开关。
- `internal/store/refund_resources.go` 及执行/恢复接入：持久清理责任、资源冷却、登录单探测及安全换号。
- `backend/refund_resource_recovery.py`：后台清理、观察、独立租约和管理员接口。
- `backend/refund_schema.sql`、`refund_settings.go`：配置、资源状态与任务表。
- `AdminRefundSettings.vue`、`RefundResourceRecovery.vue`、`AdminRefundTimeline.vue`：配置、维护列表、检查母号时间线。
- `integration/runner.py`：子号网络失败边界，详见 `refund-child-network-boundary.md`。
- `scripts/starbridge_updater.py`：更新前同时检查资源维护租约。

原注册执行核心及 HUIXU refundworker 保持来源版本。本轮经明确授权修改的 runtime 文件由 `scripts/refund_verify.py` 精确白名单核验，不能再声称全部 runtime 原样未动。

原 runtime 与新资源检查 124 项、后台资源维护 11 项、子号边界 12 项已通过；合并后重新执行 Go 全套、母号管理和分页联测、前端构建及桌面/手机浏览器回归。具体联合结果在发布记录中记载。
