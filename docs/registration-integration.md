# StarBridge 独立统一系统

StarBridge 不导入任何旧项目的用户、订单、资金、兑换码、配置或密钥。业务资源由运营人员重新配置；后续更新保留 StarBridge 自身数据。旧账户、scrypt 密码、gr_ 密钥、GR 兑换码及历史账本的接入兼容和迁移工具已移除。

## 运行结构

- `starbridge-app`：一个主应用，包含统一 Vue 页面、直接渲染的注册业务组件、Python 后端及内部注册接入模块。接入模块仅监听容器内 127.0.0.1:3210；用户不访问独立注册前台。
- `starbridge-registration-worker`：独立原注册引擎和任务执行器，完整保留原管理台。
- `starbridge-postgres`：本系统唯一 PostgreSQL；同一数据库存放统一账户和两类独立业务记录。

仅主应用对外端口 5876。没有 Docker socket 挂载到网页应用。宿主 `starbridge-updater.service` 负责准备版本与精确切换两个应用服务，不新增容器。

## 数据边界

`users`、`sessions`、`api_keys`、`redeem_codes`、`ledger` 分别为统一账户、会话、密钥、兑换码和积分钱包的权威数据。注册接口读取同一用户和余额；必要的身份关联只用于原注册引擎接入，不创建第二套可登录账户或钱包。

订阅和注册的订单、代理、执行配置、队列分别保存，互不领取任务。注册下单在同一事务冻结积分；交付凭据、订单状态和扣费在同一事务提交。失败释放该订单的冻结，不能释放订阅订单冻结；重复回调不能重复扣费。

公共公告读取 `announcements`，注册事件和审计投影到统一 `risk_events`、`audit_events`；核查状态同步。此投影只处理 StarBridge 自身的事件，不连接旧项目数据库。

## 导航

| 入口 | 内容 |
| --- | --- |
| 工作台 | 一个，不分订阅／注册 Tab |
| 订阅办理 | 二级结账链接、续费管理 |
| 注册办理 | 二级我的账号 |
| 订单中心 | 一个，订阅／注册 Tab |
| 资金中心 | 一个，订阅／注册流水 Tab；同一余额及兑换入口 |
| 开发接入、接口文档、伙伴计划 | 各一份，不分业务 Tab |
| 兑换码、风控、公告、操作审计、站点设置 | 各一份，不分业务 Tab |
| 注册账号交付 | 紧接订单中心 |
| 注册供应商统计 | 紧接资金中心 |
| 原注册管理台 | 完整管理台，统一管理员会话授权 |

注册价格、接单、队列、代理等业务参数保持独立。公共品牌、安全认证、SMTP 和登录由主应用负责。注册接单和功能开关位于同一站点设置页面；注册价格和并发位于服务与定价的注册页。

## 体验与安全

注册办理、订单和账号交付直接挂载在主页面，不使用 iframe。页面模块按需加载，查询缓存按用户隔离，退出时清除。带哈希静态资源使用缓存与 gzip；动态账户数据禁止缓存。内部 HTTP 转发复用连接池，流式响应与下载保持原样。账户页面读取不锁钱包，钱包变动保留事务锁。

## 更新

安全与认证中填写站点地址；点击“更新”从固定 GitHub 仓库获取源码并构建，网站继续运行。准备完后点击“立即重启”，等待队列空闲、备份，再使用已构建镜像切换并验证服务。倒计时只是提示，只有实际健康检查通过才显示完成。失败恢复应用镜像，不用旧数据库覆盖新数据。

必须保留 `.env`、`.registration-runtime`、`starbridge_postgres_data` 和主密钥。仅首次安装创建空库及指定管理员，后续不重置数据。原 `xufupython` 和 `gptreg` 两套正式项目继续独立运行。

## 验证

`python scripts/registration_verify.py` 核对导入清单，禁止修改注册引擎 `src/` 非 `platform/` 部分、CLI 与 `web/src/App.tsx`。针对性测试使用 PostgreSQL 18983 上的临时数据库，不执行真实供应商注册或订阅付款。测试结果和实际性能记录单独写入本轮验收报告。
