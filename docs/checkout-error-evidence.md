# 订阅异常诊断与办理总览刷新

## 范围

2026-11-19 用户授权实现、推送 GitHub 并更新正式。订阅首次 checkout HTTP 400 后重试 RefreshAccessTokenError/401，已有记录证明新版重试使用最新保存的凭据，但没有保存具体上游拒绝原因。本次补诊断及运营展示，不声称已修复上游 400，不改变请求协议、刷新、重试、代理、付款或钱包决策，不重放历史订单。

## 异步及隐私

- Go 只做有界内存采集；原 HTTP 观察器已经脱敏的错误 code/type/message/detail/title/summary 及请求标识进入私有诊断，不再全部折叠为 other。每轮最多 24 组详细错误、192 个事件。
- 输入、请求前/响应后、刷新结束记录订单范围 HMAC 版本；传输层记录实际发送的 AT/登录 Cookie 版本及同名 Cookie 标记。代理仅记地址 HMAC，代表代理会话配置，不声称测到了实际出口 IP。刷新错误后的恢复状态另记 refresh_return。
- Python 办理线程仅 put_nowait 到原有 64 槽、每份最多 256 KiB 的队列，不解析、不写盘、不占业务数据库连接。后台线程二次过滤、轮转落盘和维护只读索引；满队列丢弃、磁盘失败不改变业务结果。
- 不增加上游请求。日志 10 MiB × 5；私有异常订单索引最多 512 份，每份最多 256 KiB，保留首轮及最近三轮、每轮首尾最多 80 事件。原始秘密、任意响应正文和请求头不落盘。目录 0700、文件 0600。
- 管理员 GET /api/admin/orders/{id}/checkout-diagnostics 按需读取单文件，no-store；普通用户、匿名及客户 API 密钥拒绝。运营订单详情显示首次与后续异常，历史无索引则用既有技术记录，不编造缺失上游原因。普通用户请求链不增加诊断请求。

## 办理总览

用户追加两端总览自动刷新、选择条件立即查询。共用刷新器使用固定截止时间，busy 不重置截止时间，隐藏页面暂停、返回立即刷新，关闭详情恢复刷新。办理总览下拉、日期、管理员范围立即查询；搜索 300ms 防抖，取消旧请求、防止旧响应覆盖；修改筛选回第一页，保留分页及排序。去掉必须点击的筛选按钮，保留重置。
