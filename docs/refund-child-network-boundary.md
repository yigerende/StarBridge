# 代退子号网络故障立即冷却与切换

2026-11-12。本轮在独立工作区完成，尚未提交、推送或更新正式环境。订阅流程不变，不改历史订单、钱包、资源选择或真实代理配置。

## 故障原因与范围

11:26 的正式代退记录中，子号登录和授权请求先出现 curl 7 / CONNECT 504，原登录客户端仍在同一代理上进行内部重试。最后返回登录 401 后，调度器只依据最终错误判断，没有使用之前的网络证据，因此未冷却或切换子号代理。

用户最终确认按实际发起请求的一侧处理：所有子号阶段的明确传输/代理故障触发子号冷却及备用切换；母号故障沿用原规则，不新增母号备用。母号负责资源预检、成员/邀请查询、邀请发送、移出及确认、异常邀请清理；子号负责登录、工作空间切换、个人状态查询、导出停用及后续只读核验。

## 实现

`services/refund-core/integration/runner.py` 是星桥独立适配入口。HUIXU 的 `runtime/` 和 `internal/refundworker/` 原文件保持不变。主应用设置 `REFUND_RUNNER` 指向新入口，Docker 同时复制适配目录；运行检查与资源探测仍委托原入口。

每次执行独立子进程，在原始异常被转换或局部重试之前接收结构化传输证据。只有明确的子号网络错误或 CONNECT 407/502/503/504 才触发；密码错误、额外验证、普通 HTTP 429/5xx、母号请求不触发子号冷却。不能仅凭错误文字或最后的 401 判定为代理故障。

新增同步检查点 `child_proxy_network_failure`，在当前订单及有效执行租约下保存全局冷却和待切换标记。异步诊断队列仍只记录日志，不参与调度。冷却按故障时的当前配置计算，同一执行绑定重复通知与最终错误不会重复延长冷却。数据库确认前后都不允许继续使用故障代理执行后续子号请求；确认丢失则停止本轮，保留网络故障供最终收尾或租约恢复处理。

原调度器按照既有次数、间隔和恢复开关选择下一条可用备用，继续原订单阶段；原母号、订单及冻结不变，新单避开冷却代理。全部候选不可用时等待，不空耗重试次数；母号收尾不因此阻塞。关闭自动恢复不会被这个修复擅自开启。

导出 POST 的原先“未发送”与“结果未知”判定保留：明确未发送先保存拒绝检查点，再结束本轮；结果不明保留 submitting，下一轮只能走既有核验/兜底。换代理本身不授权重发导出、不释放冻结或宣告成功。旧租约信号不能冷却新绑定，较早任务的成功不能清除较新的冷却。
