# 代退母号轮换

原调度按母号配置更新时间排序。接单不改变该时间，零接单间隔下会持续优先使用同一个母号。

新单先沿用原资格筛选：启用、凭据有效、代理可用、无故障阻塞/残留清理/管理租约/在途占用，且已经过母号接单间隔。候选按 `last_assigned_at ASC NULLS FIRST, id` 选取：未接单优先，其次最久未接单优先。同等可用的三个母号连续接单会轮换使用；忙碌或不可用资源跳过，恢复可用后再参与。

新增可空 `refund_mothers.last_assigned_at`，在原调度数据库锁和领取事务内、建立订单绑定后用 `clock_timestamp()` 记录实际分配时间。任何后续领取错误使订单绑定和轮换记录一起回滚。无需新增上游请求或扫描历史订单，不改变配置更新时间。首次上线不改历史记录，从上线后分配开始累计；重启、编辑名称、更新AT和启停不清除轮换记录。

原单普通重试/恢复保留母号及轮换时间。原规则允许的安全换母号在清理确认等前置条件满足后参与轮换，优先其它可用母号并记录新分配。订单先来先办、并发上限、同团队互斥、接单间隔、故障冷却、子号会话、重试预算、未知提交防重与钱包结算保持。

## 验证

独立 PostgreSQL 假账号验证：9笔串行各母号3笔；进程重开和编辑配置仍持续轮换；24个并发领取者、4轮共12笔，每轮仅3个不同母号接单，总计各4笔且各订单只结算一次；不可用/过期/授权失败/故障阻塞/接单间隔优先于轮换；普通重试保持原绑定，安全切换推进新母号；领取凭据解密失败回滚订单和轮换记录。使用完整存储层和合成检查点，无真实上游调用。另用原 Worker.Run/Execute 同时执行12个不同账号，3个母号并行，模拟上游逐阶段回传，核对独立子号代理会话、母号与账号隔离、受理/完成重复回调和最终12笔单次扣费；实际最大并行执行数须为3。

发布从 GitHub 原目录构建，在新镜像和独立数据库验证后等待三业务在途、执行锁和资源租约空闲，备份再切换。新增时间字段仅为运行记录，正式资源配置、凭据和已有订单/余额保留。发布结果以生产 runbook 为准。
