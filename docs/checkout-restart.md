# 付款前提链 HTTP 400 重新办理

## 范围

Go 提链 + HTTP 直连付款流程在 `create-checkout` 返回明确的 `http_400`、尚未提交付款时，不再立即失败。原订单按配置重新排队，从建立请求会话、分配代理、生成结账链接开始。只接收提链适配器的类型化错误，不按任意异常文本匹配 400，也不把 HTTP 400 当作已确认的代理网络故障。

现有网络重试、设备标识初始化重试和付款后核实保持原规则。原注册、代退和 Go 付款核心未改。用户于 2026-11-13 明确要求推送并更新正式。沿用 GitHub 原目录拉取、预构建、隔离验证、在途空闲检查、备份切换的流程，保留正式数据和配置，不重放旧订单。最终发布结果以生产 runbook 为准。

## 配置

位置：运营控制台 → 订阅资源与调度 → 订阅流程配置 → 提链失败重新办理。

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `payment.checkout_restart_limit` 重新办理次数 | 2 | 0～5；不含首次执行，0 关闭 |
| `payment.checkout_restart_delay_seconds` 重新办理间隔 | 10 秒 | 5～3600 秒 |

订单独立持久化 `subscription_runs.checkout_restart_count`，与既有网络重试次数分别计数。共用原队列到期时间、并发控制和订单执行锁，等待不占用执行线程。新配置缺失时读取默认值，更新不覆盖已有业务配置；已打开的旧表单保存也不会清掉新配置。

## 原单与代理

- 保留原订单、用户凭据、支付地区、套餐、账单快照、价格和冻结。清空旧结账链接、结账 ID 和加密请求上下文，下一轮启动新的 Go 提链进程。
- 手动动态代理释放本单租约，按原主备规则重新选择并生成新粘性会话。IPRoyal、CLI、1024、711 均已验证。不将 HTTP 400 计入网络失败或触发供应商资源故障冷却。
- 独立会话代理删除旧订单绑定，保留供应商旧会话去重记录，下一轮调用供应商生成新会话；供应商返回旧会话时拒绝复用。
- 国家代理释放本单占用并按条目原冷却时长冷却，重新按国家池原分配规则取用地址；保留其他订单的占用和所有供应商配置。库存不足或仅有一个地址时，原池规则不能保证一定换地址。
- 固定代理无法生成新的出口。动态会话也不能保证供应商一定分配不同实际 IP；不新增出口 IP 探测请求。

## 付款与资金边界

先锁定订单及执行记录，再检查付款提交标记、已付款状态和订单状态。已提交或结果不明时保留原付款核实流程，绝不清除付款标记重付。成功订单和已结束订单不重新排队。并发重复错误报告只计一次，重试期间不解冻、不重新冻结；成功只扣一次，耗尽由原失败路径释放一次。
