# 运营代退订单账号资料

运营订单中心和办理总览的代退完整详情增加「账号资料」，点击「查看密码和 2FA」读取该订单原始提交的密码与 2FA 密钥，支持各自复制、隐藏。关闭详情或切换订单时清除页面内存中的资料并中止未完成请求；不写入 localStorage/sessionStorage，不随列表和自动刷新获取。

新增 GET /api/admin/refund/orders/{id}/credentials，使用既有管理员后端鉴权，普通用户及所有客户API密钥均拒绝。直接解密原退款订单的AES-GCM凭据（AAD为订单ID），只返回email/password/totp_secret白名单，校验邮箱和字段；不存在404，损坏、不完整或邮箱不符409，不暴露密文或异常内容。响应no-store。查看成功记录refund.order.credentials审计，只留操作者和订单号，不留密码及2FA。

用户端、对外文档、订单列表、普通详情、时间线及导出均不增加敏感字段。无数据库迁移，不修改账号凭据、订单、钱包、队列或原执行核心。历史订单保存的有效凭据可以读取，不调用上游。

验证包含3项隔离权限/历史加密数据/审计/损坏数据测试；原真实Go桥接资金并发测试核对Go创建订单的凭据解密、50并发下单/100读取/24取消及普通详情无泄漏；前端构建和1440/390浏览器查看/隐藏/复制/关闭重开/错误/办理总览/用户端隔离测试。用户已明确授权完成后推送GitHub、备份和等待在途空闲再更新正式；正式状态以production runbook为准。
