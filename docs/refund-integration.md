2026-11-10：本轮仅完成本地接入和预览，未提交、未推送 GitHub、未更新正式环境。未导入 HUIXU 的母号、代理、凭据、订单或正式配置。

## 实现边界

StarBridge 继续使用一套用户、登录、API key、会员、余额、兑换码、伙伴计划、公告、风控、操作审计和站点设置。代退加入原有工作台、运营概览、订单中心、资金中心、服务与定价及面向客户的接口文档。工作台不增加业务 Tab；订单和业务流水增加“代退”页签。

主后端仍由 Python FastAPI 统一鉴权并提供接口。原 HUIXU Go 调度和 Python 执行协议放在 `services/refund-core`，由主应用启动并监督，使用同一 PostgreSQL。Go 仅监听动态本机地址，通过进程间随机密钥通信，不对外暴露端口，不提供第二套登录或钱包。Docker 仍为主应用、原注册引擎、PostgreSQL 三个容器；没有独立代退网站或新增数据库。

Python 关闭或退出时通过 stdin EOF 停止子模块；模块意外退出时自动重启，按数据库检查点、执行租约和原恢复规则接续。健康检查在恢复期间返回 503。更新器暂停新的代退领取并等待已经开始的执行释放，保留队列和配置。此项不改变此前注册机器人对网页更新等待的既有影响。

## 功能对应

| 能力 | 星桥接入位置与行为 |
| --- | --- |
| 单个/批量申请 | 代退办理；支持 TXT/CSV 三列导入、授权确认、会员费用预览；批次整体受理或整体回滚 |
| 冻结与结算 | 提交锁定费率并冻结可用积分；原成功条件满足后扣费一次，取消/最终失败释放一次 |
| 请求幂等 | 同一用户、相同请求键返回原订单；不同内容冲突；响应未知须保留原键查询/重试 |
| 核心流程 | 邀请、登录/身份验证、原办理提交、明确受理、精确移出及确认清理；不改原步骤及判定 |
| 登录与临时故障 | 原状态分类、持久重试次数及间隔、Retry-After 等待；明确密码错误与未知提交分别处理 |
| 母号调度 | 同母号串行、不同母号 1–8 并发、团队占用、成功接单间隔、FIFO、换母号次数与等待 |
| 代理 | 子号全局代理、母号专属代理、原单固定资源和原检查能力，无直连回退 |
| 删除与重录 | 母号软删除不打断在途收尾；相同团队重新录入仍共用占用和冷却约束 |
| 异常恢复 | 原提交未知核实、清理、换号、套餐兜底、次数耗尽规则；不将未知结果伪造为成功 |
| 重启与晚到结果 | 数据库检查点 ACK、持久执行租约、旧回调拒绝及一次性费用处理 |
| 人工处置 | 管理员只读核实、确认受理/未受理、恢复清理或确认清理后释放，须填写核实依据 |
| 全流程观察 | 管理员脱敏时间线、次数、耗时、个人套餐、恢复时间、等待计划及异常占用告警；客户仅通用进度 |
| 资源与调度 | 星桥样式下的“母号资源 / 代退代理 / 调度与恢复”，原配置字段全部保留 |

“服务已完成”沿用 HUIXU 的执行成功条件，不表示银行退款已经到账。

## 面向客户的 API

统一使用 StarBridge 的 Bearer API key。公开文档包含以下五个操作，不发布管理/内部接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/refund/quote` | 当前账号报价、会员减免、受理和执行状态 |
| POST | `/api/v1/refund/orders` | 1–500 个账号的批量受理；必须带 `Idempotency-Key` 请求头 |
| GET | `/api/v1/refund/orders` | 当前账号订单列表、搜索和分页 |
| GET | `/api/v1/refund/orders/{id}` | 当前账号单笔通用进度和费用状态 |
| POST | `/api/v1/refund/orders/{id}/cancel` | 取消仍在排队的申请，释放冻结费用 |

金额为百分之一积分；完整请求/响应、状态、错误与重试示例由统一 OpenAPI 和接口文档页面提供。API key 不能访问管理接口，用户不能越权读取或取消他人订单。密码、2FA、资源凭据、原始内部日志不会返回客户。
