# 代退邮箱验证码页使用密码继续

2026-11-18：用户授权实现、推送 GitHub 并更新正式环境。

## 执行规则

账号提交邮箱后，仅明确返回 `email_otp_verification` 和 `passwordless_login`、已有密码且本次未提交过密码时，使用同一登录对象及 Cookie、子号代理继续。先 GET `/api/accounts/client_auth_session_dump`，核对当前邮箱与登录模式，再复用原 `password/verify`、TOTP challenge/verify 和回调。GET 返回 JSON，不是密码页面；HAR 证明浏览器读取了状态，不能据此断言 GET 修改登录方式。

普通办理、原单登录重试、结果核实重新登录及个人套餐兜底共用这一适配。密码或 MFA 后仍要求邮箱验证码时立即停止并保留具体原因；缺密码、手机验证、Passkey、身份不匹配不冒充成功、不循环提交密码、不抓取邮箱验证码。动态因子 ID、Cookie 和安全令牌始终来自本次登录，未复制 HAR 凭据。

调度与恢复新增“邮箱验证码页尝试密码登录”，默认开启；只补缺失配置，明确保存的关闭值不被重启覆盖。原队列、代理主备冷却、重试预算、未知提交防重、清理和冻结/扣费规则保持。运营时间线显示密码继续及后续实际失败原因，客户结果区分邮箱验证与密码后仍需邮箱验证。

原 `manager_oauth/upstream.py`、`merge_v2.py`、`internal/refundworker` 与注册引擎不改；新增星桥适配模块，来源 manifest 只更新实际修改的原接入文件。正式数据、资源、凭据与历史订单保留，不重跑历史失败单。
