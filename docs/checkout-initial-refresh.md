# 订阅提链前刷新 Session

运营控制台 → 订阅资源与调度 → 订阅流程配置 → 提链前登录态：**提链前刷新 Session**。

- 默认开启；历史配置未保存此字段也按开启处理。字段为 `payment.cslive_go_refresh_before_checkout`，只接受布尔值，旧客户端省略时保留此前值。
- 作用于 `cslive_go_direct_pay`（Go 提链 + HTTP 直连付款）创建结账链接，包括同流程独立结账链接。关闭只跳过开头主动调用 Session 刷新，不跳过首页初始化及账号检查。
- 账号查询返回 401 时仍刷新并重查。付款后的首次刷新、取消续费前的独立开关和其他流程不变。
- 每轮从原订单读取最新凭据；任何实际刷新仍先通过私有 ACK 加密持久化，再继续请求。关闭开关不禁用刷新结果保存。付款结果不明不重新付款，原冻结、结算和重试规则不变。

## 验证

合成请求与隔离 PostgreSQL 验证默认/开启/关闭、保存回显、旧客户端省略、非法类型和普通用户拒绝，订阅/独立提链转发，刷新后 400 原单重试使用最新凭据并仅结算一次，进程异常恢复及付款防重。Go 真实调用链的假上游验证默认主动刷新、关闭后直接账号查询、401 仍刷新、保存失败立即停止；无真实提链或付款请求。

前端类型检查和生产构建通过。浏览器用真实配置组件及合成存储验证缺省开启、关闭保存重开及重新开启。发布使用 GitHub 原目录预构建与新镜像隔离验收，空闲备份后切换；正式结果以部署 runbook 为准。
