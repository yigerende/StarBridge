# 代退子号按订单保存代理会话

用户要求每笔代退从登录开始复用同一子号代理会话，新增厂商、国家和会话时长配置，默认菲律宾 PH、60 分钟；完成验证后推送并更新正式，并配置已存在的皇冠、CLI、711、1024 四条子号代理。

## 生效规则

- 皇冠使用 IPRoyal 参数格式；CLI / 1024 使用 region、sid、t；711 使用 region、session、sessTime 并保留 sessAuto。每次新订单生成独立随机会话标识，旧供应商国家、会话和时长参数先替换。
- 首次领取任务时生成并加密持久化完整代理地址；执行进程一次接收，内部各步骤直接复用，不逐阶段读取数据库。普通重试、重启恢复、换母号后的重新领取、套餐兜底核验读取本单最新绑定。
- 明确子号网络故障仍按原规则冷却、选择备用。领取下一轮任务时生成备用新会话并保存；后面一直复用备用会话，主代理恢复不使本单切回。即使只剩同一家恢复可用，也生成新会话，不重用故障会话。
- 会话期限到达不会自行换会话。粘性时长是供应商参数，实际出口是否保持由供应商决定；不同会话标识不等于保证不同实际出口 IP。
- 修改资源参数不改已经保存的订单地址。代理检测使用独立测试会话，不占用业务会话。母号请求仍使用母号原绑定地址。
- 历史资源默认为“其他（原地址）”，不猜测厂商；本轮上线后只按用户明确要求修改四条现有子号资源的厂商/PH/60。保留凭据、顺序、开启状态、冷却设置和母号。

## 可见错误原因

运营订单时间线按诊断阶段和时间对应具体尝试，展示网络/TLS、手机验证、429、密码、停用受限、团队会话未就绪、MFA 409、套餐字段核验不符等固定文案。停用 HTTP 500 显示“实际结果需核验”。不输出原始上游响应或私密参数，不重写已完成登录记录。

用户此前暂停的“未知停用结果最终失败”状态机方案不在本次变更内。原提交防重、重试次数、成功判定、清理和资金结算保持；不重放历史订单、不补扣费用。

## 验证

- Go 全套真实隔离 PostgreSQL：通过，store 62.868 秒。新增覆盖四厂商参数/边界、每厂商 32 并发领取、重复故障报告、主备会话持久化、普通重试/重启/编辑/到期、兜底 Free 结算、新单同目标独立会话、具体错误时间线。
- 真实 HTTP → Python → Go 桥接：四厂商默认/保存回显、保留加密原地址、非法参数原子拒绝、普通用户 403/匿名 401；通过，15.226 秒。
- 原退款/失败保护与隔离注册钱包回归：14 项通过，54.228 秒；50 并发创建、100 隔离读取、24 并发取消，HTTP 错误 0。
- 原运行时本地双代理 HTTP 模拟：5 项通过，41.265 秒，校验登录/提交/清理各请求使用传入的子号或母号代理，没有实际外网上游请求。
- 前端构建通过，14.01 秒；1440 桌面及 390 手机代理表单保存/重新打开显示 PH、60 分钟，修改时长留空地址保存通过，浏览器错误 0。
- 来源校验通过，本轮 runtime / refundworker 与原注册核心未修改。
